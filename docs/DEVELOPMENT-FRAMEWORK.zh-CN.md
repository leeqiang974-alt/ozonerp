## 1. 主体目标

Ozon ERP 的主线是：

`1688 来源证据 → SKU/类目/属性 → 俄文内容与媒体 → 尺重采购成本 → 定价 → 预检 → 人工确认提交 → 审核回读 → 库存就绪`

订单、活动、财务和售后是运营支线，必须服务于商品生命周期，不能因为某个接口容易开发就取代黄金链路。

## 2. 五条并行工作流

| 工作流 | 目标 | 当前优先级 | 单轮交付标准 |
|---|---|---:|---|
| A 1688 黄金链路 | 一个真实商品可从来源推进到 Ozon 预检/审核 | P0 | 业务对象、阻塞原因、下一步、测试和证据 |
| B 商品与库存 | 商品状态、价格、库存写前/写后对账 | P1 | 读取/差异/确认/回查闭环 |
| C FBS 履约 | 订单读取、备货、标签、发运、取消 | P1 | 只读模型或一个明确履约动作闭环 |
| D 活动与经营 | 活动、利润、售后、报表 | P2 | 先读模型和影响预览，再考虑写入 |
| E 生产化基础 | 认证、数据库、队列、监控、备份、部署 | P0/P1 | 每轮至少关闭一个生产风险 |

## 3. 轮转规则

- 本节仅在顶层计划解除黄金链路冻结后恢复生效。
- 每轮只交付一个可验证切片，不跨多个未完成的半成品。
- 同一工作流最多连续开发 2 个切片；完成后必须回到矩阵汇总，再轮转到其他最高优先级工作流。
- FBS、活动等支线不得连续扩展证据回执、UI 和接口，而主线 A 存在未解决阻塞时必须让路。
- 每个切片结束必须同步：代码位置、测试结果、验证等级、业务剩余缺口和下一轮建议。
- 未经用户明确允许，不执行 Ozon 真实写入；真实读取也必须记录店铺、环境、时间、范围和脱敏回执。

## 4. 状态标签

每个工作流只允许使用以下状态：

`未开始 → 设计中 → 开发中 → 本地验证 → 真实只读验证 → 真实写入验证 → 暂停`

“代码存在”“接口已注册”“测试通过”不能替代业务完成状态。
