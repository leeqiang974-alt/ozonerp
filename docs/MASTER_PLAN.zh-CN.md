### 1688 云牛顿补采对接（授权基础已部署，补采任务待授权后接入）

- 云牛顿作为“网页插件无法确认 SKU 时的按链接补采”来源，不能替代正常 1688 页面采集，也不得自动重跑既有店铺采集结果。
- 其 AppKey/AppSecret/Token 与严选（JXHY）应用完全隔离；必须经 Alibaba `author` OAuth、一次性 state 校验和本地加密存储，严禁在前端、日志或仓库回显。应用不允许本机回调时使用 1688 共享 `authCode.htm` 回调页，完整返回 URL 仅回传本地换取 Token。
- 已按 OpenAPI 文档确认标准表单地址和 `newtoncloud.task.get` 只读查询格式。授权验证只允许查询随机不存在的任务号，绝不创建任务；只有收到“任务不存在”等非鉴权错误，才可判定凭据可用。当前提交的既有 author Token 在签名校验被拒绝，必须用本应用下的 author 流程重新授权后才可接入补采。
- ERP 左侧提供独立“云牛顿接入”页：AccessToken 必须仅在本机密码输入框中提交、后端加密保存且永不回显；“只读验证授权”须由运营单独确认，文档提示 API 调用可能消耗积分。严禁通过聊天接收、展示或记录 Token、code、回调 URL。
- 授权可用后，才实现只读任务轮询与“主图/详情图/SKU 图/价格/库存”分流入库；终态固定为 `END`、`KILL`、`ERROR`。
- 询盘、催单、下单、作图等外部写动作不属于补采阶段，必须单独设计确认、审计与权限边界，禁止由补采自动触发。
- 2026-08-27 新增的“按链接补采”第一步仅允许创建本地可审计任务：保存目标店铺、标准商品链接、Offer ID 与严格只读请求说明，绝不调用云牛顿、1688 或 Ozon。真实 `task.create` 只能在官方文档确认全部字段、签名与积分影响后，以运营明确点击的独立动作启动。
- 未来返回结果必须验证 Offer ID，并将公共主图、商品描述详情图、SKU 专属图分字段保存；禁止推荐图、广告或店铺素材混入，禁止猜测不存在的 SKU 组合。补采结果仅为采集证据，不自动创建草稿、AI 文案或 Ozon 提交。
- 2026-08-27 已根据官方文档确认并接入 `newtoncloud.task.create`：POST 标准网关表单，必填 `access_token`、`_aop_signature`、`message`，补充 `_aop_timestamp` 与 `auto=true`；返回 `taskId`、`sessionId`、`status`。启动必须由运营明确确认，因 API 调用可能消耗积分；`RATE_LIMIT_CONCURRENT`、`RATE_LIMIT_PENDING_TOTAL`、`RATE_LIMIT_QUEUE_FULL`、`RATE_LIMIT_HOURLY`、`RATE_LIMIT_DAILY` 等错误码原样保留在任务错误中。
- ERP 只把严格只读的商品链接采集提示词传给 `message`，不传询盘、下单或铺货意图；任务创建失败不会伪造成功状态。`task.get/fetch` 的完整返回字段确认前，不实现结果轮询和自动入库。

## 商品上架（本地草稿与预检进行中，Ozon 写回仍待阶段 7）

商品上架采用“草稿—校验—核价—审批—小批发布—任务追踪”路径。详细设计、API 对应与验收标准见 `docs/PRODUCT_LISTING_PLAN.zh-CN.md`；在 FBS 当前工作台阶段仅可开发不含 Ozon 写回的草稿和预检能力。

当前已完成本地单变体草稿、CNY 核价预检、Ozon 末级类目/商品类型缓存、中文类目选择器，以及必填属性动态表单。字典属性采用至少 2 个字的按需搜索、单次最多 50 条和 24 小时本地缓存，草稿会持久化 Ozon `value_id`；多选字典属性会逐个持久化/校验/提交 Ozon `dictionary_value_id`，不得把拼接字符串当作单个值。已保存或人工选定的属性不会被 AI 覆盖，多选草稿值会在加载时恢复为可编辑数组。增值税统一按 `0%` 提交。下一步补图片规则校验与多变体属性模型；完成审批和审计前不得调用商品导入写接口。

多变体发布的图片规则：Ozon `/v3/product/import` 按 `items.images` 的数组顺序展示，第一张即该 SKU 主图。提交时必须将每行变体的 SKU 图放在该 item 的 `images[0]`，公共详情图随后追加并去重；不能让全部变体共用商品图库的首图。

采集素材自动继承：只要草稿已绑定 `source_product_id`，创建草稿、批量生成草稿及打开历史草稿时都必须自动写入/修复公共详情图库，不得要求运营点击“从采集导入”或“回填”。修复仅移除误混入公共图库的 SKU 图，并从同一货源追加最多 15 张公共详情图；每个 SKU 的独立首图始终保留在变体行。

批量明细“重新处理”不是盲目重发旧请求：必须从绑定货源重建本地草稿，执行图片隔离、属性/内容质量预检与可自动修复；存在阻塞问题仍显示“需处理”，不得提交。只有预检通过且店铺仍有可用额度时，才允许发送 Ozon；“等待额度”只做额度复核，不得在额度仍不足时反复外发。

主题标签和标题合规是提交硬门槛：主题标签必须逐项为俄文、去重、20–30 个、每项（含 `#`）最多 30 字符，且不得含批发、促销、折扣、礼物、时尚/最佳等营销词；在 Ozon payload 中每个标签必须是属性 `23171` 的独立 `values[]` 项，禁止把空格分隔的整行当成单一值。商品标题必须删除批发、促销及无事实支撑的营销修饰。提示词不是校验边界，所有草稿在提交前都要做确定性清洗。

上品模板：运营可按店铺保存“类目 + Ozon 属性值 + 可选固定俄文描述”的复用模板，并在编辑器中一键套用。模板不会保存或覆盖商品标题、Offer ID、图片、SKU、价格、库存、包装尺寸和重量；模板绑定 Ozon 类目/类型，后续批量自动填表也应以此作为受控默认值来源。

营销活动控制：统一聚合 ERP 名下全部店铺的 Ozon 活动；支持退出所有非 CPC/CPO 的已参与活动。退出属于批量写回，必须先展示影响范围、由运营确认、按店铺保留成功/失败结果并写入审计；CPC/CPO 始终只读展示，不允许被批量退出。

自动定价控制：采用 ERP 全店铺共享、数据库持久化的参数策略。编辑器导入变体、P5 自动定价和草稿预检必须调用同一后端公式，禁止前端维护独立倍数公式。参数变更只影响之后的新报价/新导入商品，不后台静默改写已保存或已发布商品；历史商品若需重算，必须由运营明确触发。

FBS 订单工作台：订单主列表必须直接提供商品图片、商品名称、商品种数和件数预览，支持运营人员不打开详情即可识别订单；详情抽屉继续显示完整行项目。订单同步后应补拉并缓存 Ozon 商品主图，图片加载失败需显示明确占位状态。

商品编码约束：Ozon `offer_id` / SKU 编号最大 50 字符。所有生成、翻译、编辑、持久化和提交路径必须复用同一规范化规则；超长编码使用可读前缀加稳定哈希，既满足长度又保持唯一，预检必须在调用 Ozon 前阻止不合规编码。

Ozon 回拉约束：采集箱“从 Ozon 拉取”必须按 `/v3/product/info/list` 返回的 `model_info.model_id` 识别完整商品卡，并将同模型的全部 Offer ID 恢复为一个草稿的独立 SKU 行。已有草稿不得静默覆盖，必须让运营人员选择打开原草稿或确认重新拉取。


## 商品来源主线：Ozon 公共商品采集 -> 二次编辑 -> Ozon 上架

由于同一主体下店铺之间不允许直接复制商品，本项目不采用“店铺 A -> 店铺 B 商品复制”作为主流程。新的主流程是：浏览器扩展采集 Ozon 公开详情页快照，进入本地二开草稿，重写俄语内容、重做图片、重新生成 SKU 和 CNY 价格，经过质量预检、审批后再发布。公开商品采集仅保存为研究/改编来源，不直接复制品牌、图片、描述或 Offer ID。

当前已完成第一步：Ozon 详情页采集快照可通过扩展写入 `source_products`，来源标记为 `ozon_public`，并与 1688 来源保持独立幂等键。下一步是二开工作台和品牌/水印/重复内容风险预检。

当前扩展已纳入本项目 `browser_extension/erp-collector-extension`，保留 1688 采集、Ozon 详情采集、SKU 筛选和后台任务 worker；新增 Ozon 搜索列表卡片浮层。列表页只展示页面可见的评分、评价、尺重和销量提示，尺重/销量来源标记为 `capture_hint`，不得直接作为定价或物流结算依据。详情页采集会把尺重规范为 g/mm 字段并写入 Ozon 公共快照。

浏览器端采集增强已开始：列表卡片会尝试使用当前 Ozon 会话请求同源 `composer-api.bx/page/json/v2`，解析页面内嵌商品 JSON 并回填尺重/销量提示；请求失败时保留公开 DOM 结果，不阻塞页面。该路径不传输店铺 API Key。

## 1688 -> Ozon 自动上架流水线（保留为后续来源）

### 自动上品调度中心（2026-08-14 开始）

- 当前阶段调整为“夜间后台预处理 + 次日人工上架”：后台只读取严选候选、官方详情与尺重/风险证据，并保存待人工处理候选。运营必须逐项检查图片、SKU、价格、尺重与风险结果，再显式创建手动上架草稿；不启用自动 AI 推进、审批或 Ozon 提交。多店铺场景下也不得由系统自行决定目标店铺或跨店发布。
- 挂机严选采集仅收集低风险货源：危险/易燃易爆、液体喷雾、服装鞋靴、农资农药与驱虫液、工业品与原材料不可进入采集箱；详情已证实重量超过 2kg、单边超过 400mm 或体积超过 20L 的商品同样拦截。详情仍缺尺重时保留为待补候选，不得自动进入后续 AI、审批或发布。
- 新增持久化自动任务、运行批次、候选商品和事件记录；每个候选保留 Offer ID、筛选状态和淘汰原因。
- 自动执行器已接通真实严选列表与详情接口，依次执行价格/销量/48小时发货初筛、尺重和库存精筛，并将合格商品幂等写入指定店铺采集箱。
- 后台调度器每30秒检查到期任务，同一任务禁止并发；失败运行保留阶段和错误，支持后续重试。
- SKU 图片处理由独立成熟方案提供；本模块仅保留原图、SKU绑定和未来标准接口，不重复开发生成或改图。
- 最终 Ozon 发布仍需批次审批，不允许定时任务绕过预检和审批直接发布。
- 自动 AI 推进采用每轮最多3个的有界队列；真实发布采用每次最多20个的小批写回，并以每店每日180安全额度限制，保留20个平台额度用于人工补品和失败重试。
- 作图/SKU图片处理为外部可插拔阶段；当前看板明确标记“外部图片模块”，ERP只保存原图和SKU绑定，不伪造图片处理完成状态。

- 点击继续时以 Ozon `/v4/product/info/limit.daily_create` 的实时余额为准；旧额度回执不得永久屏蔽继续入口。仅实时有余额的店铺恢复其等待队列，其他店铺等待下一次额度恢复。
- 运营暂停必须在 worker 的逐商品检查和收尾状态归并中均保持为暂停，不能被队列剩余量覆盖。
- 批量继续采用连续轮转队列，不再以 200 条作为运营操作边界；某店达到 Ozon 实时创建额度后仅暂停该店，其他店铺继续，剩余商品保留等待额度状态。

### 1688 店铺采集执行原则（2026-08-25）

- 店铺商品清单扫描与详情采集采用流式生产消费：扫描页每发现并去重一个 Offer ID，立即写入可恢复详情队列；不要求先完成全店扫描，也不设置旧式100条试采门禁。
- 详情 worker 低并发领取普通队列并持续回传结果；登录、验证码、滑块或访问风控时全局转 `waiting_human`，由人工恢复后继续。
- 采集阶段只写入来源商品快照，不创建 Ozon 草稿、不调用 Ozon 发布写接口；后续批量刊登任务再复用单品上架链路。

## 2026-08-27 库存发布真实回读闭环

- 库存流程以 Ozon 导入回执、商品 `price_sent` 状态和 FBS 仓库库存回读三段事实为唯一依据；本地 `stock_sync_status` 只能展示流程进度，不能作为“已推送/未推送”的结论。
- Ozon 的 `WARNING` 可能随成功导入置于 `errors` 数组中，必须记录并展示，但不可阻断库存；只有未解决的 ERROR 才阻断对应 SKU。任何补推均须先筛出 `price_sent`、有匹配 FBS 仓库且 Ozon 回读缺失/不一致的 SKU。
- 当前待实施操作为受控补推：先将 warning 误阻断的库存监控逻辑部署，再由运营明确确认范围后写入库存并逐 SKU 回读。禁止因部署或验证自动补推。

## 2026-08-28 SQLite 恢复与全店 Ozon 库存对账

- 异常退出后的后端默认安全启动：仅当 `OZON_ENABLE_BACKGROUND_WRITES=1` 才允许启动库存写入线程、自动修正重提调度器或批量续跑；安全模式仍提供全部读取与运营显式操作接口。
- SQLite 使用短生命周期连接、60 秒 busy timeout 与外键约束。恢复前后必须用 `PRAGMA quick_check` 与 `/health` 验证，禁止手工删除回滚日志来掩盖锁问题。
- 新增 `POST /api/v1/shops/{shop_id}/inventory-reconciliation`：从 Ozon `/v3/product/list` 全量枚举商品，再读取 `/v3/product/info/list` 和 `/v2/product/info/stocks-by-warehouse/fbs`，不依赖本地草稿，覆盖历史 Offer。该接口不调用库存写接口，仅保存汇总审计。
- 对账必须区分 `price_sent` 的库存正常、库存为 0、无 FBS 记录，以及尚未 `price_sent`；只有已 `price_sent`、有可靠本地货源库存且匹配 FBS 仓库的行可进入人工确认的补推计划。
- 崩溃恢复时，已有 Ozon task ID 的 `processing` 行保留 task ID 并转“等待回执/等待额度”，绝不能自动重新排队提交；仅从未拿到 Ozon task ID 的本地处理中断行可重新排队。
- 库存补录执行后必须逐店按 SKU 记录“计划、接口接受、FBS 回读一致、拒绝原因”。`PRODUCT_HAS_NOT_BEEN_TAGGED_YET` 不是库存值错误，进入 `waiting_tag` 并至少延迟 15 分钟后复查；不得快速重试。
