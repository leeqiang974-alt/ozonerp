# 商品上架模块开发方案

本模块服务于项目北极星目标，但所有 Ozon 写操作仍受阶段 7「受控写回」约束。当前先建设草稿、校验、核价和审批，不在前端直接发布。

## 目标流程

`货源/人工录入 → 商品草稿 → 类目与属性映射 → 图片校验 → CNY 核价 → 预检 → 审批 → 小批发布 → task_id 跟踪 → 错误修正`

## Ozon API 对应

| 环节 | API | 用途 | 写入风险 |
|---|---|---|---|
| 类目选择 | `/v1/description-category/tree` | 读取末级类目与类型 | 只读 |
| 属性模板 | `/v1/description-category/attribute` | 读取必填属性、可选值和限制 | 只读 |
| 草稿预检 | 本地规则 + Ozon 属性字典 | 拦截缺图、缺必填属性、变体不完整与不合格价格 | 无 |
| 创建/更新 | `/v3/product/import` | 分批提交商品；每批最多 100 条 | 写入，必须审批 |
| 发布结果 | `/v1/product/import/info` | 根据 `task_id` 获取逐商品状态与错误 | 只读 |

## 核心实体

- `listing_drafts`：店铺、货号、标题、类目、描述、草稿状态、来源。
- `listing_variants`：规格、条码、尺寸重量、采购成本、售价、最低价、库存准备状态。
- `listing_media`：主图、附图、来源、下载/校验状态。
- `listing_validation_results`：字段级错误、警告、Ozon 属性映射结果。
- `listing_publish_runs`：审批人、批次号、请求摘要、`task_id`、Ozon 返回、重试记录。
- `listing_audit_events`：草稿变更、价格覆盖、审批和写回操作。

## 必须通过的预检

1. 店铺已配置、处于启用状态，且类目和属性来自当前 Ozon 字典。
2. 每个变体均有货号、可识别规格、重量与尺寸；必填属性不允许空值。
3. 图片 URL 必须可访问；主图存在，图片数量与格式符合 Ozon 限制。
4. 所有金额为 CNY；通过利润、物流、佣金和最低价规则校验，`min_price < price`。
5. 无重复 Offer ID；同一批次无互相覆盖的变体；库存写回尚未启用时明确标识为“仅建卡”。
6. 只有全部校验通过且被授权人员审批的批次才能发送写 API。

## 开发顺序

1. 商品草稿、变体、媒体和校验结果的持久化模型及中文 UI。
2. 类目树/属性字典只读同步和可搜索的类目映射界面。
3. CNY 定价试算、图片/属性/变体预检，以及可导出的错误清单。
4. 审批与发布批次：先模拟发送 payload，记录完整审计。
5. 仅对已批准的小批次启用 `/v3/product/import`；轮询 `task_id`，支持逐项修正后重试。

## 验收标准

- 运营可在不调用 Ozon 写 API 的情况下完成草稿、校验、核价和审批准备。
- 任何缺图、必填属性缺失、非 CNY、利润/最低价违规或重复货号都无法进入发布批次。
- 真正写回前可查看 payload 摘要、审批人和影响 SKU；写回后可按 `task_id` 追踪到每项结果。
