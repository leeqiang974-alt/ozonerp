# Ozon ERP 顶层开发执行计划

版本：2026-07-23

状态：`active`

唯一目标：用户手工采集一个真实 1688 商品后，ERP 自动处理到“预检通过、等待人工确认提交”。

## 1. 成功定义

近期 MVP 不是“所有 ERP 模块都有页面”，而是一个真实商品能够连续完成：

`手工采集 1688 → 来源快照 → SKU/图片/采购/尺重归一化 → Ozon 店铺类目与属性 → 俄文内容 → 定价 → 本地草稿 → 一键预检 → 少量人工确认 → 等待提交`

MVP 达成必须同时满足：

1. 使用至少 1 个真实 1688 商品，不用只为测试构造的理想数据冒充完成。
2. 从采集导入到预检之间只有一个当前商品和一个明确下一步，不要求用户操作开发者工作流节点。
3. 能自动确定的字段自动完成；不能确定的字段集中成卖家任务，说明原因、输入要求和处理结果。
4. 同一输入可重复运行且不生成重复商品、重复 workflow 或跨店铺数据。
5. 任何来源、类目、属性、尺重、价格或媒体证据不足都必须 fail-closed。
6. `npm test`、lint、runtime smoke 和离线验收通过；真实读取与真实写入分别记录验证等级。
7. 在 MVP 通过前，不以订单、活动、财务、售后、报表或通用平台化工作代替主线进度。

## 2. 当前范围冻结

### 必须开发

- A：1688 手工采集到 Ozon 预检的单商品黄金链路。
- E：仅限黄金链路直接需要的认证、店铺范围、Seller API 只读、持久化和启动可靠性。
- B：仅限商品提交成功后必需的审核状态回读和库存就绪交接。

### 暂停开发

- C：FBS 备货、标签、发运、取消及其扩展 UI。
- D：活动加入、财务利润、售后、报表和经营大屏。
- 新导航、新大屏、新评分系统、通用 workflow 平台、非黄金链路的“顺手重构”。
- 对已经本地通过但尚无真实业务样本的边缘规则继续深挖。

暂停项只有两种恢复条件：MVP 阶段 G4 已通过，或它构成当前黄金链路的直接阻断并在本计划中登记。

## 3. 执行纪律

1. WIP 限制为 1：任何时刻只有一个 `CURRENT` 切片。
2. 新任务必须能映射到本计划的一个阶段和一个退出条件；不能映射则不开发。
3. 每个切片最多解决一个主要业务结果；发现旁支问题先写入停车场，不立即扩展。
4. 仅以下问题可中断当前切片：服务无法启动、数据丢失/损坏、凭据泄露、可能绕过真实写入安全门。
5. 单点修复不得无限扩大。超过当前退出条件所需的工作，必须拆为后续切片。
6. 每次提交必须记录：对应阶段/切片、用户结果、测试、验证等级、剩余阻断。
7. 阶段未通过退出门，不得把后续阶段标记为进行中。
8. 真实 Ozon 写入仍必须由用户针对具体商品和具体 payload 明确确认。

### 时间盒

- 一个实现切片目标为 1–2 个工作日；超过 2 个工作日仍未达到退出条件，必须停止扩展并报告真实阻断、已验证事实和缩小方案。
- G1–G4 的集中开发目标为 14–22 个有效工作日，前提是能及时取得一个真实 1688 样本和受控 Seller API 只读条件。
- G5–G6 预计再需要 10–20 个有效工作日，取决于真实提交、审核和库存回读结果。
- 时间盒用于限制范围，不允许通过降低安全门、跳过真实证据或把 partial 标成 completed 来“按时完成”。

## 4. 阶段计划

| 阶段 | 业务结果 | 主要交付 | 退出条件 | 当前状态 |
|---|---|---|---|---|

| G1 可信采集入口 | 手工采集结果稳定进入一个本地商品 | 采集输入契约、来源身份、SKU、图片、采购、尺重、快照回执 | 1 个真实 1688 商品可重复导入；缺失信息变成明确任务 | `completed` |
| G2 自动商品草稿 | ERP 自动生成可审查的 Ozon 草稿 | SKU/Offer、俄文内容、媒体、包装、定价、店铺绑定 | 同一商品生成唯一草稿；自动字段完整；未知字段集中展示 | `CURRENT` |
| G3 真实类目属性 | 草稿使用当前店铺真实 Seller API 只读证据 | signed session、类目树、属性、字典值、证据绑定 | 目标店铺真实只读回执绑定草稿；不跨店/环境复用 | `pending` |
| G4 一键预检 MVP | 用户只处理少量必要确认，草稿进入等待提交 | 当前商品工作台、修复任务、强预检、重跑 | 真实商品从导入连续走到“预检通过/等待确认提交” | `pending` |
| G5 受控提交审核 | 用户确认后提交，并读取审核结果 | payload 对照、幂等提交、未知结果复核、审核回读 | 1 个受控商品真实写入并取得审核回读 | `pending` |
| G6 库存就绪 | 已审核商品安全进入库存准备 | Offer×仓库只读、dry-run、确认写入、写后回查 | 精确 tuple 写后回查完成 | `pending` |
| G7 批量与生产化 | 单商品闭环稳定后才扩展规模 | 队列、重试、监控、备份、批量控制 | 多商品可控运行且故障可恢复 | `pending` |

## 5. 当前阶段 G1 的唯一切片队列

### G1-S1 `completed`：手工采集输入契约与现状核对

用户结果：明确“手工采集时必须提供什么”，并确认现有扩展/导入接口哪些字段真实可用、哪些只是代码存在。

交付：

- 盘点两个 1688 扩展、capture API、持久化文件和草稿入口的真实字段流。
- 固化一个版本化 `manual_capture_v1` 输入/回执契约。
- 禁止把缺失采购、尺重、SKU 或媒体证据悄悄补成可信事实。
- 建立一个可脱敏保存和重复回放的真实商品样本入口。

退出条件：

- 契约测试覆盖单 SKU、多 SKU、缺字段和人机验证页面。
- 导入结果明确返回：已自动完成、需要用户补充、被阻断及下一步。
- 不调用 Ozon、不执行付费模型、不生成商品写入。
- 扩展、crawler detail 回传和 `/api/1688/capture` 统一使用 `manual_capture_v1`；未知契约版本在解析前阻断。
- 全量验证：`npm test` 1240/1240、lint 75 文件、offline acceptance 通过；未联网、未连接数据库、未执行 Ozon 写入。

### G1-S2 `completed`：采集导入的卖家操作入口

用户结果：用户手工采集后，可以在 ERP 中看到唯一的当前商品、导入结果和下一步，不需要理解 capture JSON 或 workflow 节点。

本切片只解决：

- 采集成功后自动打开/定位当前采集箱记录，并显示契约版本、来源身份、快照、SKU/图片/采购/尺重覆盖和阻断项。
- 采集失败、重复采集、需要补尺重、人机验证分别给出卖家动作；重复采集必须复用同一商品上下文。
- 为 G1-S3 的真实商品回放准备可脱敏导出/导入入口；不在本切片生成 Ozon 草稿。

退出条件：

- 一个本地 fixture 可通过同一入口完成导入、重复导入和缺字段恢复。
- 当前商品入口不会落到旧商品、旧店铺或无关 workflow。
- 插件采集成功或重复采集后自动打开带 `captureId` 的当前商品入口；ERP 回传完整脱敏回执。
- 定向测试、全量 `npm test` 1240/1240、lint 75 文件和 offline acceptance 均通过；未联网、未连接数据库、未执行 Ozon 写入。

### G1-S3 `completed`：首个真实 1688 商品回放

- 使用一个真实商品完成采集、导入、重放和重复导入验证。
- 修复真实样本暴露的主链断点；边缘类目问题进入停车场。
- G1 通过后才能开始 G2。

退出证据：

- 真实 1688 Offer `992997159052` 由 Chrome 扩展采集进入店铺 `3815760-4`，持久化 ID `c178476424685142rv6`。
- 真实回执包含 18 行 SKU 采集结果（归一化后为 9 个唯一来源 SKU）、28 张图片、19 个属性和绑定快照；同店铺同 Offer 重复导入仍只有 1 条记录并复用同一 ID。
- 缺失供应商身份与采购 MOQ/阶梯价保持 `needs_review`，没有伪造成可信事实；卖家下一步明确为补齐后重采并预检。
- 修复整页消息过大与 loopback Chrome 扩展 CORS 两个真实主链阻断；未调用 Ozon、未执行付费模型或商品写入。
- 全量 `npm test` 1247/1247、lint 76 文件、runtime smoke、offline acceptance 通过。

## 5.1 当前阶段 G2 的唯一切片

### G2-S1 `CURRENT`：真实采集商品生成唯一草稿骨架

用户结果：当前真实采集商品进入一个店铺绑定、可重复打开的本地 Ozon 草稿上下文，不再停留在采集回执。

本切片只解决：

- 从 `c178476424685142rv6` 生成或复用唯一的本地草稿/工作流上下文。
- 保留 18 行原始采集计数供审计，并以 9 个唯一来源 SKU 与快照绑定进入草稿；缺失采购、供应商、可信包装尺重和媒体合规证据继续作为集中任务，不猜测类目属性。
- 重复执行必须复用同一草稿，不调用 Seller API、不生成付费内容、不提交 Ozon。

退出条件：

- 当前商品页能打开唯一草稿，并显示自动带入字段、阻断项及唯一下一步。
- 同一 capture/store/snapshot 重跑不生成重复草稿或 workflow。
- 定向测试、全量测试、lint 与 runtime smoke 通过；无 Ozon 写入。

当前进度（2026-07-23）：

- 已实现 capture/store 维度的唯一草稿骨架和 workflow 复用；重复执行不会新增草稿或 workflow。
- 已实现来源 SKU 去重，优先保留字段更完整的重复行，并记录原始行数、唯一 SKU 数和重复行数。
- 卖家确认精确快照后，界面会立即进入当前商品草稿并集中展示阻塞项与唯一下一步。
- 本地验证已通过：`npm test` 1253/1253、lint 76 文件、loopback runtime smoke、offline acceptance；并发 8 次仍只产生 1 个 job/1 个 workflow，跨快照刷新与缺少来源 SKU ID 均 fail-closed；未联网、未连接数据库、未调用 Seller API、未执行付费模型或 Ozon 写入。
- 阶段仍保持 `CURRENT`：真实 capture 尚需用户在界面完成一次精确快照确认，以形成真实草稿回执并验证 9 个唯一 SKU 与阻塞清单。

## 6. 阶段级验收清单

每个阶段结束时必须回答：

- 用户现在能完成什么以前不能完成的事？
- 使用了真实数据、fixture、mock 还是纯静态检查？
- 哪些字段仍需人工，为什么不能自动？
- 是否发生网络、数据库、模型费用或 Ozon 写入？
- 失败是否停在安全、可恢复、可解释的状态？
- 下一阶段的唯一入口是什么？

## 7. 停车场

以下问题可以记录，但在 G4 通过前不得主动领取：

- FBS 履约写动作。
- 活动加入和活动自动定价。
- 完整财务、退款、利润和售后。
- 通用 BI、经营报表和新仪表盘。
- 与当前真实样本无关的类目边缘规则。
- 批量无人值守、自动图片生成和大规模性能优化。

## 8. 计划变更规则

- 只有用户明确改变顶层目标，或真实样本证明阶段顺序不可执行，才修改阶段顺序。
- 修改时必须说明原因、受影响阶段、迁移方式和新的退出条件。
- 日常 bug、代码清理和“顺便优化”不能改写顶层计划。
- `docs/ROADMAP.zh-CN.md` 记录已交付证据；本文件决定下一步做什么。
