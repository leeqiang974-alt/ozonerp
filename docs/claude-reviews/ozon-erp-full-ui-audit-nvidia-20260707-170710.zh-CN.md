1. **业务问题重述**  
当前 Ozon ERP 前端存在系统性信息架构混乱：核心业务模块边界模糊，非本模块内容（如上架字段）错误出现在订单、营销等非相关界面；HTML/DOM 结构脆弱，业务区块脱离语义容器（如 #listing）；诊断与高级工具（如自动化预览、AI 生成建议）压倒主业务操作路径；普通卖家无法清晰识别“当前在做什么、下一步安全操作是什么、点击后会发生什么”；自动化安全闸（如 preflight、waiting_human、GPT 成本确认）在 UI 中未显式呈现，存在合规风险。

2. **受影响的 ERP 模块所有权边界**  
- **Listing（上架）**：必须仅包含 Ozon 草稿、类目、属性、标题、描述、图片、定价、preflight、提交闸口。禁止出现订单状态、仓库库存、促销产品、财务利润等字段。  
- **Orders（订单）**：仅允许展示 FBS 订单状态、履约节点、物流异常。禁止出现产品属性、采集图、变体设置、描述、类目等上架字段。  
- **Promotions（营销）**：仅允许展示促销规则、参与商品ID、移除按钮。禁止出现任何上架字段（标题、描述、图片、属性表单）。  
- **Workflow Console（任务控制台）**：仅允许展示阻塞节点、字段定位、重试、源替换、提交闸口状态。禁止展示原始采集数据、AI 图像生成建议、定价计算逻辑。  
- **Dashboard（仪表盘）**：仅允许展示今日风险、当前产品状态、明日行动建议。禁止展示任何编辑表单、采集源、仓库库存、促销配置。

3. **必须不被绕过的安全闸**  
- Ozon preflight 校验（类目合规、属性完整性、图片合规）  
- 显式人工确认（提交前弹窗：确认价格、图片成本、GPT生成内容）  
- waiting_human 状态锁（阻塞自动化流程，等待人工介入）  
- 浏览器人机验证暂停（CAPTCHA/滑块验证未通过时禁止继续）  
- GPT/图像生成成本确认（费用超阈值时必须弹窗授权）  
- 被阻断的定价风险（价格低于成本或违反 Ozon 限价规则时禁止提交）

4. **需检查或修改的文件（仅限变更列表）**  
- public/index.html — 检查 DOM 结构是否符合模块容器契约（如 #dashboard、#listing、#orders、#promotions 是否独立封闭）  
- public/app.js — 检查路由与模块加载逻辑，确认无跨模块数据注入（如订单页调用 listing 属性生成器）  
- public/styles.css — 检查是否通过 CSS 误将非本模块内容“视觉隐藏”而非“逻辑隔离”  
- docs/erp-ui-information-architecture.zh-CN.md — 对照当前实现，验证模块边界定义是否被违反  
- docs/superpowers/specs/2026-07-07-auto-ozon-style-erp-shell-design.md — 验证“auto-ozon shell”是否仅为视觉层，未重构业务逻辑归属  
- docs/superpowers/plans/2026-07-07-ozon-erp-automation-cross-development.md — 检查自动化流程是否绕过安全闸设计  

5. **可能新增或运行的测试**  
- test/frontend-static.test.js — 扩展测试：验证每个主模块的 DOM 容器内是否仅包含其合法子元素（如 #listing 内无 .order-status 元素）  
- 新增 test/module-boundary-ownership.test.js — 检查每个页面加载后，是否无非法模块字段注入（如订单页无 attribute-form）  
- test/auto-listing-payload-draft.test.js — 增加校验：确保提交前 payload 不含来自非 listing 模块的字段（如来自 promotions 的 discountRule）  

6. **验收标准**  
- 所有核心模块界面中，禁止出现非本模块业务字段（如订单页无产品描述、促销页无图片上传区）  
- 所有自动化流程（如 autoListing）在触发前必须显示明确的安全闸 UI（如“GPT 图像生成费用：¥12.5，确认继续？”）  
- 所有业务操作路径遵循：标题 → 所有权契约 → 任务卡片 → 关键业务面板 → 折叠高级内容  
- public/index.html 中，每个模块容器（如 #listing）为独立 DOM 树根，无跨模块元素嵌套  
- docs/erp-ui-information-architecture.zh-CN.md 与实际 UI 完全一致，无描述与实现偏差  

7. **风险或与现有规则冲突**  
- 若“auto-ozon shell”仅做视觉映射（如用 CSS 隐藏字段而非逻辑隔离），则违反“模块边界严格”规则，构成系统性架构欺骗。  
- 若将诊断工具（如字段定位、源替换）直接嵌入主业务面板（如上架页底部），则违反“UI 规则：关键业务面板在前，高级内容折叠”原则。  
- 若为提升效率而“自动跳过 waiting_human”或“合并 GPT 成本确认到后台”，则违反“永不绕过安全闸”核心规则，将导致合规风险与卖家责任不清。  
- 若重构时试图“一次性统一所有模块结构”，将违反“开发规则：先加测试，再做小范围修复”原则，应分阶段推进。  

> **建议重构阶段**：  
> 第一阶段（低风险）：仅修复 DOM 容器结构（如 #listing 重新包裹所有上架字段）、移除跨模块字段注入、增加模块边界测试。  
> 第二阶段（中风险）：重构模块加载逻辑，确保 app.js 不跨模块注入数据。  
> 第三阶段（高风险）：重设计自动化流程与安全闸 UI，必须经用户确认后方可推进。  
> **任何涉及安全闸、定价、GPT 成本、人工确认的改动，必须等待用户书面确认后方可实施。**
