# Ozon ERP 前端信息架构重构说明

更新日期：2026-06-29

## Figma 规划图

- 功能归属地图与上架主流程图：<https://www.figma.com/board/sy7fZ0JGQI5QCRYKCLdAXY>

## 一级导航

ERP 前端按 5 个一级区组织，避免采集、AI、上架、运营和系统配置混在一起。

1. 今日工作台：日常入口，只看待处理、阻塞、风险和可继续动作。
2. 商品上架流水线：1688 采集、上架草稿、工作流节点诊断。
3. 学习与素材：Ozon 样本、图片风格、GPT 单品指导、GPT Image 2。
4. 店铺运营：商品状态、仓库库存、订单履约、营销活动。
5. 系统配置：店铺 API、类目字典、Seller API 对齐、开发缺口和高级诊断。

## 上架主流程

主流程固定为：

1688 采集 → 商品解析 → Ozon 同品参照 → 分类与属性 → 文案与图片 → 定价与利润 → 提交前校验 → 提交 Ozon → 审核回馈。

每个节点应该只回答三件事：

- 当前状态是什么。
- 下一步该点哪个按钮。
- 出错时应该改哪个字段或切换哪个策略。

普通卖家不再逐节点操作这条流程。默认上架页收口为一张单商品编辑单：系统自动填写类目、属性、SKU、图片、文案、尺重和价格结果；俄罗斯站点、俄语、克、毫米等稳定默认值直接应用；AI 文案通过一次明确点击生成。只有来源确实缺失、候选歧义、测量数据未知或真实提交确认等无法安全自动化的项目才展开输入框。节点、证据、JSON 和回执只在折叠高级区保留。

## 首页核心任务

首页最上方增加“上架一个商品”结果面板，不再让用户先理解所有模块。该面板只回答：

- 当前商品是谁。
- 现在卡在哪。
- 为什么不能继续。
- 下一步点哪个入口。

状态来源优先读取最近 workflow、阻塞节点、最近采集商品和最近自动上架任务。若没有当前商品，默认引导到 1688 采集；若有阻塞节点，默认引导到工作流控制台；若已采集未生成草稿，默认引导到上架草稿。

## ERP 运行逻辑

首页增加“ERP 运行逻辑”业务模型，不再让用户先看开发者式模块和日志。ERP 先按卖家每天真实要处理的事情组织：

1. 今天先处理什么：系统自动汇总当前商品、审核失败、库存风险、订单待处理和价格风险；用户只决定先处理哪个。
2. 商品生命周期：系统自动推进 1688 货源、Ozon 草稿、预检、提交和审核回馈；用户只决定货源、类目、字段修复或换货源。
3. 店铺日常运营：系统自动读取商品状态、库存、订单和活动；用户处理补库存、订单、改价和活动维护。
4. 异常与决策：系统把失败翻译成业务原因；用户只在推荐动作中选择修资料、换货源、重新生成、确认继续或放弃。

原则：不再把“人工干预”作为默认语言。界面必须说清楚问题、原因、用户要决定什么、点了以后会发生什么。

## 当前商品流程

9 节点流程面板默认只显示当前商品或当前选中 workflow 的状态，不再聚合全部历史 workflow 的待人工、失败数量。历史任务只在折叠的“历史统计”里展示数量摘要，具体旧问题进入工作流控制台处理。

这样普通操作员看到的是：

- 当前商品的每个节点是否完成、失败、等待人工或未运行。
- 当前商品在该节点的具体问题。
- 当前商品下一步应该进入哪个模块。

历史的 91 个待人工、87 个待人工这类数字不再出现在主流程卡片上，避免把后台事故统计误认为当前商品状态。

## 功能区归属契约

每个一级功能页必须在页面顶部展示“当前功能区 / 本页处理 / 本页不处理 / 错页提示”。这不是装饰文案，而是防止 ERP 功能串区的硬约束：

- 今日工作台：只处理今天优先级、当前商品、店铺风险和继续推进入口。
- 1688 采集：只处理 1688 货源采集、采集箱、候选解析和生成上架草稿。
- 上架草稿：只处理 Ozon 上架草稿、类目属性、标题描述、图片、价格、预检和提交闸口。
- 节点诊断：只处理流程卡点、错误原因、字段定位、重试、换货源和提交闸口。
- Ozon 参照与图片：只处理样本参照、图片风格、文案指导和图片生成建议。
- 商品状态：只处理 Ozon 商品列表、状态、价格和异常观察。
- 仓库与库存：只处理仓库读取、库存读取、库存写入和库存失败队列。
- 订单履约：只处理 FBS 订单、待备货、待发运、运输中、取消和争议状态。
- 营销活动：只处理 Ozon 活动读取、活动商品、可加入商品和移出活动。

特别规则：如果“营销活动”页出现“平台分类、无忧易售信息、描述、产品采集图、标题、类目属性”等上架字段，就是路由或内容归属错误，必须按串区 bug 修复，不能把这些字段解释成营销页能力。

## Tab 页面层级

每个 tab 不允许一打开就是完整长表单或开发者式工具堆叠。页面默认层级固定为：

1. 页面标题：说明当前模块。
2. 功能区归属契约：说明本页处理什么、不处理什么。
3. 任务入口卡：用一句话说明“这个页面先做什么”，并提供 2-3 个下一步按钮。
4. 关键业务面板：只露出当前最可能要操作的 1-2 个区域。
5. 高级内容：默认折叠，通过“展开本页高级内容”查看。

原则：普通卖家进入任意 tab 后，应该先看到“我要在这里完成什么”，而不是先看到几十个输入框、日志、诊断表和实验工具。高级内容保留，但不能压在主任务前面。

## 视觉与导航原则

- 整体从深色科技诊断台调整为浅色业务操作台，优先保证可读性、可理解性和长时间使用舒适度。
- 左侧二级导航全部常显，不再要求先选中一级图标才能知道里面有什么。
- 一级窄栏只作为快速定位，二级导航展示完整功能归属。
- 高级诊断继续折叠，普通用户默认看到业务模型、当前商品、商品流程和店铺管理。

## Seller 店铺管理边界

ERP 不是只有“上架工具”，还要覆盖 Seller 日常管理。首页增加“Seller 店铺管理”范围面板，把能力归属拆为：

1. 新品上架：采集、参照、草稿、预检、提交、审核修复。
2. 商品状态：在售、审核、失败、缺价、缺库存和异常定位。
3. 库存与仓库：仓库读取、库存写入、失败队列、库存回查。
4. 订单履约：FBS 订单看板、待备货、待发运、运输中、取消和争议。
5. 营销活动：活动读取、参与商品、候选商品、移出活动和后续活动价策略。
6. 利润与价格：采购价、运费、佣金、原价、最低价、利润风险诊断。

原则：普通用户先看“上架一个商品”和“Seller 店铺管理”；高级诊断、API 对齐、模块归属地图默认继续收起。

## 边界原则

- 学习与素材只为上架提供指导，不直接提交 Ozon。
- GPT Image 2 只有人工点击确认后才调用，避免自动扣费。
- Ozon 提交必须经过预检和人工确认。
- 高级诊断默认收起，不作为普通操作入口。
