# Ozon ERP 流程驾驶舱前端设计

更新时间：2026-06-21

## 目标

在不改变现有 ERP 业务逻辑和 API 行为的前提下，重构前端信息架构与视觉系统。主要使用环境为 27 寸宽屏显示器，同时保证 Codex 侧边窄屏和普通笔记本可用。

核心目标：

- 把九个平级 tab 整理为清晰的功能层级。
- 让“采集 → 分析 → 上架 → 审核 → 库存”成为页面主轴。
- 让高风险、等待人工和失败诊断优先于普通统计信息。
- 建立统一的深色科技感设计系统，但不牺牲中文可读性和表格效率。
- 保留全部现有功能、DOM 业务选择器和 API 调用。

## 信息架构

### 一级导航

左侧 72px 图标导航只保留四个一级区域：

1. **驾驶舱**：运营总览、工作流中心。
2. **商品全链路**：Ozon 学习、1688 选品、上架执行。
3. **运营管理**：商品与库存、订单履约、营销活动。
4. **系统**：店铺、API 状态、安全模式和配置。

### 二级导航

展开区域使用约 220px 二级侧栏，展示当前一级区域的具体页面。原有页面 ID 和 `data-view` 保持不变，只调整入口归属和显示名称。

原功能映射：

- `dashboard` → 驾驶舱 / 运营总览。
- `workflow-console` → 驾驶舱 / 工作流中心。
- `research` → 商品全链路 / Ozon 学习。
- `sourcing` → 商品全链路 / 1688 选品。
- `listing` → 商品全链路 / 上架执行。
- `products`、`warehouse` → 运营管理 / 商品与库存。
- `orders` → 运营管理 / 订单履约。
- `promotions` → 运营管理 / 营销活动。

## 驾驶舱布局

主内容按以下优先级排列：

1. 顶部全局栏：页面标题、全局搜索、新建上架、当前店铺和 API 状态。
2. 高风险提示条：等待人工、变体合并失败、库存阻断等需要立刻处理的事项。
3. KPI 卡：运行中工作流、等待人工、今日上架成功、库存健康。
4. 商品全链路：采集、分析、上架、审核、库存五个可点击节点。
5. 当前工作流焦点：只展示最需要处理的任务，提供直接进入诊断的入口。
6. 系统脉冲：Seller API 延迟、采集器、队列、学习样本等运行信号。
7. 原有模块归属和 Seller API 对齐说明降级为可折叠说明区，不再占据首屏。

## 页面结构

### 工作流中心

- 保留运行列表、节点时间线、详情面板三栏结构。
- 顶部增加筛选、搜索和风险摘要。
- `waiting_human`、`listing_defect`、`stock_sync` 使用明显但克制的状态色。
- Payload 编辑器和危险提交动作保持原安全确认机制。

### 上架执行

- 按“基础信息、类目属性、变体、图片与内容、提交预检”拆成步骤区域。
- 默认突出当前步骤，已完成区域收起为摘要。
- 变体表保留高密度编辑能力，不改字段含义和提交格式。

### 商品与库存

- 商品状态与库存归入同一运营区，但仍保持独立页面和 API。
- 商品异常状态提供进入工作流诊断或受控修复的入口。
- 库存写入结果与 `stock_sync` 节点保持关联。

## 视觉系统

### 颜色

- 页面底色：`#07101C`。
- 一级侧栏：`#08111F`。
- 面板：`#0B1829` 至 `#0E1D30`。
- 边框：`#203650`。
- 主强调色：青色 `#47E3FF`。
- 操作蓝：`#2359F3`。
- 成功：`#50E5B0`。
- 警告：`#FFB15E`。
- 阻塞：`#FF6B7A`。

状态色只用于状态、风险和关键动作，不用于大面积装饰。

### 字体与间距

- 使用系统字体栈，中文优先 `Microsoft YaHei UI`，数字优先等宽或 tabular numerals。
- 页面标题 22–28px；区块标题 14–16px；正文 13–14px。
- 卡片圆角 12–16px；输入框和按钮圆角 9–11px。
- 统一 4px 间距基线，常用间距 8、12、16、20、24px。

### 动效

- 只使用 120–180ms 的 hover、选中和面板切换过渡。
- 不使用持续闪烁、粒子背景或影响性能的光效。
- 高风险提示可以有一次性轻微高亮，不循环动画。

## 响应式规则

- `>= 1440px`：72px 一级栏 + 220px 二级栏 + 主内容。
- `1024px–1439px`：一级栏保持，二级栏可折叠为 64px。
- `< 1024px`：侧栏变为抽屉，顶部保留当前页面和菜单按钮；禁止导航整块堆到内容上方。
- 表格在窄屏内横向滚动，不强制把所有列压缩到不可读。

## 数据与业务边界

- 不修改后端 API、业务状态机、数据文件或 Ozon 提交规则。
- 复用现有 `state`、`load*`、`render*` 和事件处理函数。
- 通过新的壳层、导航配置和通用组件样式包装现有页面。
- 保持自动化安全状态、人工确认、Payload 校验和 Ozon 提交确认逻辑不变。

## 错误与空状态

- API 离线：顶部显示离线状态，相关操作禁用，但页面仍可查看本地数据。
- 无数据：使用简短说明和一个明确主动作，不展示空白大表格。
- 高风险：提供原因、影响和唯一推荐动作，避免同时出现多个相互冲突按钮。
- 长任务：使用节点状态和局部 loading，不使用覆盖全屏的长时间遮罩。

## 实施顺序

1. 建立主题变量、应用壳层和两级导航。
2. 重构驾驶舱首屏和业务主链。
3. 统一通用卡片、表格、状态、按钮、表单和空状态。
4. 逐页整理工作流、上架、选品、商品库存、订单和营销。
5. 增加宽屏、笔记本和窄屏响应式测试。
6. 在真实页面进行视觉回归，不改变业务测试预期。

## 验收标准

- 27 寸宽屏首屏能看到全局状态、待人工提示、四个 KPI、五节点主链和工作流焦点。
- 不再出现窄屏侧栏占据整个首屏的情况。
- 九个原页面均可通过新导航进入，功能与 API 请求不回退。
- 高风险和等待人工状态能在三秒内被识别。
- 所有危险操作仍保留人工确认和安全闸。
- 前端静态测试、全量测试和 lint 全部通过。
- Chrome 宽屏、1366px、1024px 和 Codex 窄屏至少各完成一次视觉检查。
